# v0.5.2

## Highlights

- TUN TCP buffers are back to smoltcp's 8 KiB default. [0.5.1](https://github.com/cablehead/pai-sho/blob/v0.5.2/changes/v0.5.1.md) raised them to 256 KiB, on the reasoning that an 8 KiB window chopped a large Datastar patch into pieces that each waited for an ACK. Measured over a real link, the larger buffers were slower and less consistent: a 300 KiB write took a median 62ms to arrive with the 8 KiB default, and 154ms with 256 KiB. That is a scripted sequence of writes over a live tunnel, timed from the start of each write to its last byte, with the connection's own round trip subtracted. The reason is not established. The buffers belong to the userspace TCP stack `--tun` creates, so the machine to upgrade is whichever daemon runs with it: on macOS the one under `brew services`. A daemon without `--tun` is on kernel sockets and gains nothing from this. The two ends do not have to be on the same version.
- `pai-sho list` now prints version numbers: the `pai-sho` that ran the command, the daemon that answered it, and every peer. Peers send theirs on connect. A peer running 0.5.0 or 0.5.1 shows no version, because those releases do not send one. Nothing else changes, and daemons on either version still talk to each other.

```nushell
pai-sho list | from json | get peers
| select name version online admission they_expose
| update they_expose {|r| $r.they_expose | str join ", "}
╭───┬─────────────┬─────────┬────────┬───────────┬─────────────╮
│ # │    name     │ version │ online │ admission │ they_expose │
├───┼─────────────┼─────────┼────────┼───────────┼─────────────┤
│ 0 │ buildbox    │ 0.5.2   │ true   │ key       │ 8080        │
│ 1 │ vibenv-ndyg │         │ true   │ code      │ 3001, 7331  │
│ 2 │ tower       │ 0.5.2   │ false  │ added     │             │
╰───┴─────────────┴─────────┴────────┴───────────┴─────────────╯
```

`vibenv-ndyg` is online and still blank: it is running a release that does not announce. `tower` is offline and keeps the version from when it last connected.
